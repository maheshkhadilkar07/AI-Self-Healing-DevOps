Methodology — algorithms & techniques

Six techniques, each with a working implementation and a place on the dashboard where you can see it run.

1Isolation Forest— Anomaly detection

Detects abnormal CPU, memory, latency, error-rate and traffic patterns. Trained on healthy data only; paired with a z-score guard because the forest alone cannot measure how far a value is outside its training range.

selfheal/anomaly.py
2Random Forest / XGBoost— Failure classification

Classifies a detected failure into CPU overload, memory exhaustion, database failure, container crash or bad deployment. This prototype uses Random Forest on baseline-relative features; XGBoost is a drop-in alternative.

selfheal/classifier.py
3Correlation + service dependency graph— Root-cause analysis

Walks the dependency graph to the deepest anomalous service and confirms propagation with latency correlation between services.

selfheal/rca.py
4Cosine similarity— Historical incident retrieval (RAG retriever)

TF-IDF vectors of symptom descriptions; the most similar past incidents are retrieved from the knowledge base and shown with their similarity score.

selfheal/knowledge_base.py
5Rule-based decision algorithm— Remediation selection

Maps diagnosed failures to safe actions: container crash → restart, high load → scale, bad deployment → rollback. A policy engine validates every action first.

selfheal/remediation.py, policy.py
6Threshold / health-check algorithm— Recovery verification

Checks that CPU, memory, latency, error rate and throughput have returned to acceptable levels for several consecutive checks; otherwise retry, then escalate to a human.

selfheal/verifier.py
